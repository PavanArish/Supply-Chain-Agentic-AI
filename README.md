# Supply Chain Agent

An agentic AI supply-chain decision-support platform. Upload a shipment/
supplier/inventory file, ask questions in plain language, and get back
insights, charts, recommendations, and risk alerts — generated by an
orchestrator that plans and runs specialized agents.

Architecture matches the diagram: **React + Tailwind** frontend →
**FastAPI** backend (Auth, File Upload, Query, Results, History APIs) →
Input Processor (read/clean/profile) → AI Orchestrator (Agent Manager) →
6 specialized agents (Disruption, Root Cause, Forecast, Inventory, Risk,
Recommendation) → Data Analysis & Tools layer (Pandas/NumPy, scikit-learn,
stats) → Data Storage (SQLite by default, MySQL-ready) → External service
stubs (News/Events API, Maps/Route API).

## Quick start

### 1. Backend (FastAPI)

```bash
cd backend
python3 -m venv venv && source venv/bin/activate   # optional but recommended
pip install -r requirements.txt

cp .env.example .env   # already done for you; edit if needed
python run.py
```

The API runs at `http://localhost:8000`. Interactive docs at
`http://localhost:8000/docs`.

**LLM is optional.** Without `GEMINI_API_KEY`, `GROQ_API_KEY`, or
`GROK_API_KEY` set in `.env`, the orchestrator and agents fall back to
deterministic rule-based logic, so the whole app works end-to-end for
free. Add any one key to let a real LLM pick agents and write the
natural-language summary instead:

- **Gemini** (free tier) — get a key at https://aistudio.google.com/app/apikey
- **Groq** (GroqCloud, free tier, Llama/Mixtral) — get a key at https://console.groq.com/keys
- **Grok** (xAI — a different service, easy to mix up with Groq) — get a key at https://console.x.ai

If more than one is set, priority is: Gemini, then Groq, then Grok.

**Database:** defaults to SQLite (`storage/app.db`), created automatically
on first run — nothing to install. To use MySQL instead, edit `.env`:

```
DATABASE_URL=mysql+pymysql://USER:PASSWORD@localhost:3306/supply_chain_agent
```

(Create that database first: `CREATE DATABASE supply_chain_agent;`)

### 2. Frontend (React + Vite + Tailwind)

```bash
cd frontend
npm install
cp .env.example .env   # already done for you; points at localhost:8000
npm run dev
```

Open `http://localhost:5173`.

### 3. Try it

1. Sign up for an account.
2. Upload a `.csv` or `.xlsx` with shipment/supplier/inventory data (any
   column names — they're auto-detected).
3. Ask something like *"Find delayed shipments and identify the top
   suppliers causing delays"*.
4. View insights, charts, recommendations, and risk alerts. Download a
   report as CSV, Excel, or PDF. Past queries are saved under History.

## Project layout

```
backend/
  app/
    core/          # config, db session, security, auth dependency
    models/        # SQLAlchemy models: User, Dataset, QueryHistory
    schemas/       # Pydantic request/response schemas
    services/      # column mapping, cleaning, dataset/report services,
                    # LLM wrapper, external API stubs, df cache
    agents/        # 6 specialized agents
    orchestrator/  # Agent Manager (selects & runs agents)
    routers/       # auth, datasets, query, history, reports
  run.py
  requirements.txt
  .env.example

frontend/
  src/
    pages/         # Login, Dashboard
    components/    # FileUpload, DataPreview, QueryBox, ChartCard,
                    # ResultsPanel, HistorySidebar, Navbar
    context/       # AuthContext (JWT session)
    api.js         # API client
  .env.example
```

## Notes / next steps

- The **News/Events API** and **Maps/Route API** boxes in the architecture
  are wired up as stubs (`app/services/external/`) — add real API keys in
  `.env` and fill in the marked spot in each file to go live.
- Raw spreadsheet rows are **never** sent to the LLM — only small computed
  JSON summaries are, per the design decision baked into `llm_service.py`.
- The in-memory DataFrame cache (`app/services/df_cache.py`) speeds up
  repeated queries against the same upload within a server's lifetime; it
  reloads from disk automatically after a restart.
